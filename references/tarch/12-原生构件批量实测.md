# 天正 V10 原生构件批量实测

> 这是版本和日期相关的命令参考。连接、命令选择和实测范围以 [天正连接机制](../tarch-joins.md) 及当前环境为准。

## 已验证的本机范围

2026-11-19 在 T20 天正建筑 V10 / AutoCAD 2024 上，使用 7 段天正墙、毫米单位的合成示意图，通过隔离 CAD 进程验证：

- `TOpening` 选自由定位后，墙边基线点投递可一次生成 3 个普通门 `TDbOpening`。三段墙洞面积实际分别增加 1.60、1.89、1.60 m²，修改其中一樘为 900×2100 mm 后重开仍一致。门点要落在宿主墙边，不是简单取墙体中心点。自由定位键为 `HKCU/Software/Tangent/TArch/20V10/Settings/Door` 的 `InsertMode=0`；脚本记录并在正常结束时恢复旧值。默认顺序模式的一次测试曾因选墙失败而没有创建门。
- `TRStair` 一次生成 2 个 `TDbRectStair`，高度 3000/3200 mm、各 20 步并只读重开。高度改动可能联动改变步数；应根据资料重新核对梯段、平台、朝向和上下层连接。
- `TElevator` 一次连续生成 2 个天正电梯门和 20 条 `EVTR` 层简图线，两段宿主墙洞各增加 2.31 m²，门为示例 1100×2100 mm。每井按“两角点、门在实际宿主墙线上的定位点、平衡块侧点、无其他门”的顺序投递，整批结束再退出命令。保存并用天正只读重开，分别检查原生电梯门 `TDbOpening`、宿主墙真实断口和 `EVTR` 层二维简图。该版本的这批命令输出由门对象和简图线组成。井道围护、轿厢或设备厂家参数的完整性须按各自证据验收。井道原有电梯门时，核查同一位置的重复开洞、重复门扇以及简图覆盖关系。
- 窗类型切换仍未稳定；在隔离进程冷启动前设 `bDoorControl=0` 仍只生成普通门。`TGColumn` 投递 3 点但未生成可回读柱；`TSan` 等待选择且未生成可核验洁具。不得将它们说成已跑通的批量流程。

所有尺寸仅为示意。

## 2026-11-20 独立天正实例只读重开

- **门窗。** 交付图保留 75 个原生 `TDbOpening`。逐樘核对真实墙洞、门窗与宿主墙的双向实体关联及非零洞口面积，包含用官方命令直接落墙的斜向门和 4 樘柜门。阶段图的 12 樘原生门曾验证更换独立 `340` 二维图库引用后保留门句柄、宽高、原 `330` 宿主关联及真实墙洞，其中双扇 10 樘、推拉 1 樘、卷帘 1 樘。图例、镜像及重开核对见[门窗](04-门窗.md#斜墙原生开洞与图库核对)。
- **电梯。** 用天正官方 `TElevator` 生成的 13 组设备简图均保留，每组是 `EVTR` 层上 10 条图线。13 樘井壁门是原生门窗实体，保留真实墙洞及宿主墙的双向关联。已有有效原生门的井道可在隔离试样中生成官方简图，将核对过的简图定位到对应井内，再检查原门、墙洞及井道围护。
- **幕墙。** 3 段同心弧和 5 段直线幕墙独立重开均保留原生 `TDbCurtainWall` 类。阶段图已核对半径、厚度和原墙替换。流程见[直线与弧形原生幕墙](03-墙体与柱.md#直线与弧形原生幕墙)。
- **楼梯。** 独立重开保留原生直线 `TDbLineStair`、圆弧 `TDbArcStair` 和矩形双跑 `TDbRectStair`。异形斜墙处按原图可见梯跑拆分为原生直线梯段，并对照实际围护内墙面核查踏步、剖断辅助线和中间投影空区。多段拟合的实际总高和单步标高待现场核实。详见[楼梯场地](06-楼梯场地.md#斜墙约束下的双跑楼梯平面)。
- **出图。** 按构件对应的出图分类复核内外墙、柱、窗、楼梯和玻璃的显示，并检查相互交接的实际出图。

## 脚本与使用方式

`scripts/tarch/native_batch_demo_v6.py` 调用同目录 `native_batch_worker_v5.py`，读取 `native_demo_spec.json` 中的门和双跑楼梯；`scripts/tarch/native_elevator_batch.py` 调用同目录 `native_elevator_worker_v4.py`，读取 `elevator_demo_spec.json`。脚本依赖本机 AutoCAD 2024、天正 V10 的安装位置及 Python `pywin32`，会启动隔离的图形化 CAD 进程，不代表 Core Console 或无界面运行。

从技能根目录运行。先准备含原生墙的测试 DWG，并把两个 spec 副本中的句柄、坐标和尺寸改为与测试图一致。公开包只提供参数样例。将下例的源图和 spec 路径换成实际路径，输出使用新文件名。

```powershell
$project = Join-Path $env:TEMP ('tarch-demo-' + [guid]::NewGuid())
New-Item -ItemType Directory -Path (Join-Path $project 'output') -Force | Out-Null
$skill = (Resolve-Path './scripts/tarch').Path
$source = (Resolve-Path (Read-Host "测试 DWG 路径")).Path
$doors = (Resolve-Path (Read-Host "与该图匹配的门和楼梯 spec 路径")).Path
$lifts = (Resolve-Path (Read-Host "与该图匹配的电梯 spec 路径")).Path
$env:PYTHONIOENCODING = 'utf-8'
python "$skill\native_batch_demo_v6.py" --project $project --source $source --spec $doors --output "$project\output\门楼梯复跑示意.dwg"
python "$skill\native_elevator_batch.py" --project $project --source $source --spec $lifts --output "$project\output\电梯复跑示意.dwg"
```

脚本复制源图到 `tmp`，要求新输出位于项目 `output`，检查源文件哈希并在保存后只读重开，生成同名 JSON。已存在输出会拒绝覆盖；若程序中断后只出现 DWG 而没有核验记录，应视为未验证。启动时 CAD COM 接口可能短暂忙碌或未就绪；失败不要直接将候选图当成成果。

参数示例中的墙句柄、坐标、门尺寸和楼梯数据只适用于合成图；不能照搬至项目。门的检查依赖墙边和洞口面积；电梯示例的门墙点先检查落在墙包围范围内，随后检查墙洞面积；这些检查不证明门方向、墙柱拼接、净宽和空间流线全部正确。普通门和双跑楼梯均采用天正当前可用默认样式，需另行核对宽度、方向等未指定属性。本节合成复跑脚本的墙体覆盖范围为简单正交墙。运行期间避免并行操作同一用户的天正门插入设置；进程遭强制终止时需检查并恢复该设置。

实际图纸须先理解建筑外墙、各空间、门窗与流线，依据已知资料决定各构件参数；不明确之处标注现场核实，再逐项核查墙柱、门窗、电梯、楼梯和上下层关系。
