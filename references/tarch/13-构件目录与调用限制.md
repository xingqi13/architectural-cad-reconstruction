# 天正 V10 构件目录与调用限制

> 这是版本和日期相关的命令参考。连接、命令选择和实测范围以 [天正连接机制](../tarch-joins.md) 及当前环境为准。

## 先区分目录与实体

`scripts/tarch/tarch_component_catalog.py` 只读本机 T20 V10 的 `lvtry.DBF` / `lvtry.DWB`、`Column.tk` / `Column.DWB`、`WinLib2D.TK` / `WinLib2D.DWB` 和 `SYS/TCommonOpenning.xml`。它提取活动项、删除状态、名称、编号及候选图库目录匹配关系，并输出 JSON；**不会在 CAD 中插入对象**。DWB 目录解析是依据本机文件结构得到的候选匹配，并非厂商发布的通用格式说明，遇头部、长度或索引异常即停止；不写回厂商安装文件。

2026-11-19 本机数据：

- 洁具 DBF 总计 288 条，其中 203 条标记删除，85 条活动；85 条中 83 个编号可在同名 DWB 的目录候选项中匹配。`0000000a` 小便池和 `0000000b` 盥洗槽未匹配，不要因此推断它们无法使用或可以直接作为普通块插入。
- 柱图库 TK 总计 111 条，其中 52 条活动、59 条删除；52 条中有 50 条含绘图编号，均在对应图库目录找到候选编号。它们是图库样式记录，不等于已验证的 `TDbColumn` 创建接口。
- 窗二维样式 TK 总计 71 条，其中 12 条活动、59 条删除；12 条活动样式在图库目录有候选编号。普通窗参数预设 XML 中有 3 条。样式或预设不等于生成了天正窗及宿主墙洞。

复跑方式（输出必须是不存在的新文件）：

```powershell
$project = Join-Path $env:TEMP ('tarch-demo-' + [guid]::NewGuid())
New-Item -ItemType Directory -Path (Join-Path $project 'output') -Force | Out-Null
$skill = (Resolve-Path './scripts/tarch').Path
$env:PYTHONIOENCODING = 'utf-8'
python "$skill\tarch_component_catalog.py" --output "$project\output\天正构件目录复跑.json"
```

选型时依据项目资料读取输出 JSON 中活动记录，使用 `KIND`/`DESC`/`BLOCK` 或 `KIND`/`ITEM`/`DRAWING` 过滤；不得将已删除项、候选匹配或示例尺寸当作可用及已验收构件。

## 2026-11-19 隔离复测

- 窗：可读到“插窗”选项，但当前自动化界面未提供可点击坐标，屏幕捕获超时；参数面板切换未成功。以既有天正门为样本测试 `HoleType`、`GetSubKind`、`HoleStyle`：`HoleType` 是洞口形状，尝试写入窗类别被拒绝；其他属性写入后仍回读普通门，不能据此变窗。按用户反馈选窗并退出后重新进入命令，3 个墙边点被接收，但未生成窗或墙洞；重新进入后的选型状态尚未确认。
- 柱：`TGColumn` 的面板显示标准矩形柱参数，AutoLISP `command` 的 3 次点位输入均到达提示，但模型空间没有新增对象；已加载环境中 `AddCustomObject` 对 `TDbColumn`、`TCH_COLUMN` 及已知墙、楼梯类名均返回无效类字符串，不能将此方式视为可用创建接口。
- 洁具：以活动目录编号 `00000171` 尝试多种 AutoCAD `InsertBlock` 名称（含 `lvtry(00000171)`）均失败；天正 DWB 索引不能直接当成 AutoCAD DWG 块名。`TSan` 的图库选择、方位及沿墙插入仍未完成自动化验证。
- 使用图形界面工具粘贴坐标时，天正拦截为 `TPasteClip`，不应将粘贴误当成点位已输入。后续优先找厂商支持的创建/选型接口，或在测试副本中仅选一次类型后用已验证的 CAD 命令流连续输入，并通过实体计数、几何、墙洞及只读重开验收。

不得声称窗、柱或洁具的全自动批量插入已通过。
